# ComponentMatch Agent 需求说明

版本：2026-10-23 前后端分离版。后端、Streamlit 前端与公共接口契约均已实现。
当前目录与启动方式见根 README；当前验证范围见 [验证索引](verification.md)，历次结果见 [历史目录](history/README.md)。

## 1. 业务理解与成功定义

面向采购人员：把单条电子元器件采购需求转为可校验条件，在**给定模拟数据集、
明确硬约束与已公开评分规则下**，推荐最多三家不同供应商，并给出可核对的依据。
“最优质”指本次需求下的综合适配程度，不是对供应商的永久评级或真实性背书。
同一家供应商对不同型号、数量、交期和权重可以有不同排名。

面向面试：能解释需求理解、图工作流、数据建模、确定性决策与模型边界，
可现场展示正常匹配、补充条件、无结果与模型故障。这些后端分支已实现并使用离线模型替身验证。

## 2. 范围与用户故事

| 编号 | 用户故事 / 功能 | 预期行为 |
| --- | --- | --- |
| F01 | 采购员输入中文自然语言需求 | DeepSeek 提取结构化字段，Pydantic 校验；展示解析条件 |
| F02 | 采购员未提供完整条件 | 列出缺失/冲突字段和具体补充问题，不猜数量、型号后缀、预算或资质 |
| F03 | 采购员希望准确匹配料号 | 制造商 + 完整料号精确识别；同型号跨制造商歧义时追问 |
| F04 | 采购员有硬性采购要求 | 先过滤型号、库存、起订量、包装倍数、交期、预算、必需证书 |
| F05 | 采购员希望比较供应商 | Python 计算分项分、权重与总分，返回最多三家不同供应商 |
| F06 | 采购员希望理解推荐 | 展示真实计算证据、来源、排除原因和风险；LLM 只能解释这些证据 |
| F07 | 采购员遇到无供应商可用 | 返回空排名与按原因汇总的排除统计；不得自动放宽硬约束 |
| F08 | 演示遇到模型或网络故障 | 解析失败明确报错，可改用显式结构化输入；解释失败用模板 |
| F09 | 面试官检查可信度 | 页面与响应始终标注模拟数据、数据时间、规则版本与解释方式 |

不在范围：真实库存/报价/证书核验、爬虫、BOM 多行联合优化、自动替代料认证、
跨供应商拆单、自动超量采购、阶梯价/多币种/汇率、物流费及税务结算、下单、
支付、登录、多租户、ERP 对接、微服务、向量检索和多 Agent 协作。

## 3. 输入契约

结构化端点为 `POST /api/v1/matches`；独立自然语言端点为 `POST /api/v1/agent/matches`：

- `natural_language`：`text` 非空，最多 2,000 字符；走 LLM 解析。
- `structured`：用户填写并提交完整 `requirement`；直接校验，响应明确标注未调用解析模型。

补充条件采用“返回待补充字段 → 用户提交 confirmed_fields 或完整结构化需求”的方式，
每次提交都是新请求。不依赖服务器聊天记忆，也不通过拼接历史文本猜测覆盖关系。

| 字段 | 类型与单位 | 必需性 / 规则 |
| --- | --- | --- |
| `part_number` | 字符串 | 必需，完整制造商料号；禁止自动删除后缀 |
| `manufacturer` | 字符串或 null | 可缺省；若目录存在多个制造商同名料号则必须补充 |
| `quantity` | 严格正整数，pcs | 必需；“1k”仅在语义清楚时转为 1,000；“一批”须追问 |
| `delivery_mode` | `unspecified / within_days / unconstrained` | `unspecified` 必须补充；“尽快”只表示偏好，仍需确认上限或明确不限 |
| `max_delivery_days` | 非负整数，自然日或 null | `within_days` 时必需；`unconstrained` 时必须为 null；0 表示当天 |
| `max_unit_price_cents` | 非负严格整数，人民币分/pcs 或 null | 含税单价硬上限，不含运费 |
| `total_budget_cents` | 非负严格整数，人民币分或 null | 含税货款合计硬上限，不含运费；单价×采购数量必须满足 |
| `currency` | 固定 `CNY` | 默认值须展示；明确其他币种时返回不支持，不擅自换算 |
| `required_certifications` | 证书代码列表 | 可选，默认空；未知证书代码返回不支持；空列表不代表已验证资质 |
| `preference_profile` | `balanced / cost / delivery / quality` | 默认 balanced 并展示；“便宜优先”等映射至已定义档位 |

所有有界数值需进行大小、单位与字段间一致性校验；预算小数用 Decimal 精确转分，
超过两位小数须澄清，不默默四舍五入。拒绝 bool 冒充整数、负数、NaN 和无穷值。
结构化接口直接接受整数分，自然语言接口通过 Python 校验原文符号、数值和单位后精确换算；两个预算字段独立且可同时生效。数量上限10亿，预算上限9×10^18分。
“含糊预算”“大概交期”“单价及总价互相矛盾”等不得被静默解释为无约束。
明确日期由 Python 从原文检查与转换，即使模型未返回交期字段也不能遗漏。
支持 YYYY-MM-DD、YYYY/MM/DD、YYYY年M月D日：无时区的日期按 Asia/Shanghai 日历日解释；
“不晚于/当天/裸日期”包含当日，“之前/以前/前”不包含当日。上限为截止日与业务日期的日差。
ISO 时刻必须带 Z 或 ±HH:MM；转 UTC 后按剩余完整 24 小时向下取整，不承诺不足一天的额外交期。
时间戳的“之前”在恰好整天边界再减一日。时区名称、日期后单独附偏移、无时区具体时刻要求澄清。
过去/无效日期、缺年份、多个冲突日期、日期与天数/交期不限冲突均要求澄清；不自动选择一个条件。
图开始时捕获业务时间；检索后按匹配服务的实际业务时间复核，如跨午夜等导致转换结果变化则重新确认。
完整性规则覆盖带片/颗/pcs或“数量”标签的数量、单价/总预算及元/片写法、ISO9001、TI/厂家标签、
自然日天数和上述日期。明确已知模式的模型遗漏/数值更改会阻断推荐。
原厂授权、授权代理、车规、温度、工作日、不支持的证书/币种会阻断；保守检查也可能要求否定表达重新说明。
这些规则不保证识别任意自然语言，其他措辞、上下文和模糊表达仍需核对与人工确认。
多型号需求返回 `needs_clarification`，提示本版一次只提交一个型号。
仅有功能描述（如“一个低功耗运放”）需要补充料号，不进行语义替代搜索。

解析草稿还须保留 `unhandled_constraints` 与 `ambiguous_constraints`：
例如“必须原厂授权”“车规等级”“指定温度范围”等本版没有可验证字段的硬条件，
不能在字段白名单过滤后悄悄丢弃。已明确不支持的条件返回 422 / UNSUPPORTED_CONSTRAINT，
含义待明确的条件返回 needs_clarification；两者都不进入排名。
Pydantic 能保证结构和数值规则，不能证明模型完整提取了所有条件；界面必须展示解析条件，
允许用户检查并用结构化表单更正。这是本版已知限制，不宣称已解决所有语义遗漏。

示例输入（仅需求示例，不代表任何库存或结果）：

> 采购 TI 的 LM358DR，1000 片，7 个自然日内到货，单价不超过 1 元，
> 必须有 ISO9001，质量优先。

结构化值为 quantity=1000、max_delivery_days=7、max_unit_price_cents=100、
preference_profile=quality；制造商别名使用受控目录映射，
本例料号存在于 DEMO 目录；其他目录中不存在的型号应返回无匹配，不临时编造数据。

## 4. 硬约束、软偏好与确认

硬约束决定能否参加排名，软偏好只选择评分权重。默认仅精确料号且同一制造商可用，
不开放 `allow_substitutes`。相似名称、封装不同、后缀不同、电气参数相近均不是兼容证据。
制造商别名允许受控映射，料号仅去首尾空白和统一 ASCII 大小写；不移除中间字符。

每条候选为“供应商对一个明确元器件的一条有效供货记录”。单家单条报价必须足量，
且能按需求数量准确订购；不合并多条库存，不拆单，不默认多买。
推荐是采购决策支持；系统不输出已下单、已锁价或已预留库存等状态。

## 5. 输出契约

业务结果统一包含 `request_id`、`status`、`input_mode`、`requirement`、
`clarification_questions`、`recommendations`、`exclusion_summary`、`warnings`、
`error`、`metadata`。无适用值时返回 null 或空集合，不使用虚构占位供应商。

- `status`：`success / needs_clarification / no_match / error`。
- 每项推荐：rank、supplier_id、offer_id、component_id、厂家与完整料号、
  单价/货款合计、数量/库存/交期、分项原值/分项分/权重/贡献/总分、证据、风险。
- `metadata`：`data_label=DEMO`、`is_mock=true`、dataset_version、business_time、实际执行 UTC 时间、
  rule_version、权重快照；结构化接口 model_name=null、explanation_mode=none；Agent 成功响应记录模型名及 llm/template 解释模式。
- 证据引用记录 ID、字段、值、来源时间；排名和数值字段只由后端构建，LLM 无覆盖权限。
- 符合者不足三家时返回实际数量；零家返回 no_match，不凑足三个。
- 排除统计针对报价记录，可一条记录有多个原因；同时给出检索数、通过数、不同供应商数，
  各原因计数之和可能大于排除记录数，页面须说明统计口径。

有效业务分支（含缺条件、无匹配）用 HTTP 200；请求外壳不合法用 422；
不支持的显式业务范围用 422 及稳定错误码；LLM 解析不可用用 503，
处理预算耗尽用 504，内部/数据库错误用 500。工作流错误含 request_id 与稳定错误码；请求外壳校验使用 FastAPI 的标准 422 detail；
不得向界面暴露异常堆栈或密钥。解释模型失败且已有评分时仍为 200 success，标明模板降级。

## 7. 已知问题与边界

1. 人工权重与阈值尚未经真实采购专家验证，只能说明方法合理、可调整，不能证明采购最优。
2. 模拟历史表现不代表现实可靠性；证书字段仅展示校验流程，不是外部认证查询。
3. 预算统一为人民币含税货款；物流费未知，无法承诺全口径采购总成本。
4. 无实时锁库存与动态报价，结果仅对展示的数据快照成立。
5. 固定业务时钟只用于显式测试模式；默认业务模式使用实际 UTC 时间和上海业务日期，
   数据集时间只描述快照，不覆盖业务时钟；本版业务数据仍全部为 DEMO。
6. 自然语言解析可变；可重复性保证从**校验后的结构化需求**开始，不声称 LLM 完全确定。
7. 原文依据和未处理条件能帮助发现解析问题，仍不能形式化证明无遗漏；本版没有自动下单。
